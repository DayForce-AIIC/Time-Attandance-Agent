# ADR-005: Retry once, then escalate

## Context
Provider output can be malformed, ungrounded, or outside deterministic constraints.

## Decision
Run one retry with failed-check feedback. If the second attempt fails or the provider is unavailable, store an `ESCALATE` fallback with no suggested timecard correction.

## Consequences
Transient model mistakes can recover, while repeated failures end in a safe, visible manager workflow. The retry count stays bounded and fault modes are reproducible.
