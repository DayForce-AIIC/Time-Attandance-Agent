# ADR-002: Flat correction schema

## Context
The frozen API contract carries several correction actions in one proposal and decision shape.

## Decision
Use one strict `ProposedCorrection` object with optional action-specific fields. Pydantic forbids extra fields and validates required/forbidden fields for the selected action.

## Consequences
The API and UI share a simple contract, and each action remains easy to serialize. Validation is required to prevent incompatible optional fields from coexisting.
